# 밀담 (Mildam)

서버 없이, 공개 릴레이로 암호문만 주고받는 종단간 암호화(E2E) + 전방
비밀성(PFS) 메신저입니다. 순수 HTML/CSS/JS로 만든 설치형 웹앱(PWA)이며,
운영자가 유지하는 서버가 하나도 없습니다.

- 대화 내용은 두 사람 외에는 아무도 읽을 수 없습니다 — 중개하는 릴레이도,
  집에 둔 도우미 기기도 마찬가지입니다.
- 상대가 꺼져 있어도 메시지를 보낼 수 있습니다. 상대가 나중에 앱을 열면
  밀린 메시지가 도착합니다.
- 장기 신원 키가 유출돼도 (첫 왕복 이후의) 과거 대화는 복호되지
  않습니다(더블 래칫).
- 갤럭시(Android Chrome/삼성인터넷)와 아이폰(iOS Safari 16.4+) 모두에서
  홈 화면에 설치해 쓸 수 있습니다.

이 저장소의 구현 사양은 [`PLAN.md`](./PLAN.md)에 전부 정의되어 있습니다.

## 배포하기 (GitHub Pages)

1. 이 저장소를 GitHub에 올립니다(이미 올라와 있다면 건너뜁니다).
2. 저장소 **Settings → Pages**에서 Source를 "Deploy from a branch"로,
   브랜치를 배포하려는 브랜치(예: `main`)의 루트(`/`)로 지정합니다.
3. 몇 분 후 `https://<사용자명>.github.io/<저장소명>/` 주소로 접속되면
   배포 완료입니다. 별도의 빌드 과정이 없습니다 — 저장소의 정적 파일이
   그대로 서빙됩니다.
4. 두 사람 모두 그 주소로 접속한 뒤, 폰에서 "홈 화면에 추가"(Android
   Chrome/삼성인터넷의 메뉴, iOS Safari의 공유 버튼)로 앱처럼 설치합니다.

로컬에서 미리 확인하려면 이 폴더에서 아무 정적 서버나 띄우면 됩니다. 예:

```
python3 -m http.server 8080
```

그다음 `http://localhost:8080`으로 접속합니다.

## 사용법

1. **처음 실행**: 이름을 입력하고 "시작하기"를 누르면 이 기기의 신원(암호
   키)이 만들어집니다. 신원은 기기 안에만 저장되며 어디로도 전송되지
   않습니다.
2. **친구 추가**: ＋ 버튼을 눌러 내 초대코드를 상대에게 전달하고, 상대의
   초대코드를 받아 붙여넣습니다. **직접 만나서, 또는 이미 신뢰하는 다른
   채널로** 코드를 주고받으세요. 서로 상대의 코드를 등록해야 대화가
   시작됩니다.
3. **대화하기**: 연락처를 눌러 채팅방에 들어갑니다. 상단 배지가
   "🔒 암호화 연결됨"으로 바뀌면 전송할 수 있습니다. 내가 보낸 메시지는
   ✓(전송됨) → ✓✓(상대가 받음)로 바뀝니다. 전송에 실패하면 ⚠가 뜨며,
   탭하면 다시 보냅니다.
4. **안전코드 확인**(선택): 채팅방 상단의 🔑 버튼을 누르면 8자리씩 8묶음의
   코드가 나옵니다. 두 사람의 화면에 뜨는 코드가 같으면 대화 상대가
   바꿔치기되지 않았다는 뜻입니다. 직접 만나거나 영상통화로 서로 읽어
   맞춰보세요.
5. **알림 받기**(선택, §16 참고): 알림은 서버 없이는 원천적으로 불가능한
   기능이라, 집에 상시 켜둔 기기(도우미)가 대신 담당합니다. 도우미를
   설치·실행하는 방법은 [`helper/README.md`](./helper/README.md)를
   보세요. 도우미를 실행하면 화면에 도우미 코드가 출력되는데, 이 코드를
   설정 화면의 "도우미 코드"에 붙여넣고 "도우미 등록" → "알림 켜기"
   순서로 누르면 됩니다. 두 사람 모두 각자의 폰에서 이 과정을 해야 각자
   알림을 받습니다.

## 정직한 한계

서버를 두지 않기로 한 선택에는 대가가 따릅니다. 아래 한계는 "버그"가
아니라 의도된 설계이며, 앱 안에도 같은 내용이 안내되어 있습니다.

| 한계 | 이유 |
|---|---|
| 알림은 **도우미 기기가 켜져 있을 때만** 옵니다. 도우미가 꺼져도 메시징 자체는 정상 동작합니다 | 알림 발송에는 상시 구동 기기가 필요합니다. 도우미는 바깥 방향 연결만 쓰므로 공유기 설정은 필요 없습니다 |
| 알림에는 발신자·내용이 없습니다("새 메시지가 도착했습니다"만) | 도우미는 암호문만 볼 수 있어 구분할 방법이 없습니다 |
| 릴레이·도우미는 수신자 공개키(수신함 주소), 암호문 크기, 접속 IP를 볼 수 있습니다. 발신자는 은닉되고 시각은 최대 ±2일 무작위화됩니다. 내용은 절대 볼 수 없습니다 | Nostr NIP-17/44/59 프로토콜의 특성입니다 |
| 어떤 대화든 **첫 왕복 이전**의 메시지는 장기키 유출 시 복호될 수 있습니다(그 이후는 매 왕복마다 키가 바뀌어 보호됩니다) | 상대가 부재중이어도 첫 메시지부터 암호화하기 위한 구조적 대가입니다(Signal도 비슷한 예외가 있습니다) |
| 상대가 아주 오래(수 주 이상) 접속하지 않으면 메시지가 유실될 수 있습니다 | 공개 릴레이 4곳 중복 발행 + 도우미의 30일 재발행으로 완화합니다 |
| 이 저장소를 서빙하는 호스팅(GitHub Pages)이 악성 코드를 서빙하면 이론상 보안이 깨집니다 | 웹앱의 근본적 한계입니다. 코드 전체가 공개되어 있어 누구나 검증할 수 있습니다 |
| iOS는 PWA 저장소를 드물게 정리할 수 있어 신원 키가 사라질 위험이 있습니다 | 앱이 `navigator.storage.persist()`로 지속 저장을 요청하지만 완전한 보장은 아닙니다 |
| 도우미로 권장하는 구형 맥(macOS 11 등)은 보안 업데이트가 종료된 OS일 수 있습니다 | 도우미는 바깥 방향 연결만 하고 대화 복호 키를 갖지 않으므로 위험이 제한적입니다. 다른 용도로는 병행 사용하지 마세요 |

## 만들지 않은 것 (비목표)

그룹 채팅, 음성/영상 통화, 파일·이미지 전송, 다중 기기 동기화, 계정
백업/복구, QR 코드 스캔, 앱 잠금(PIN), 저장 메시지 at-rest 암호화, 알림
내용 미리보기. 자세한 이유는 `PLAN.md` §1.1·§2를 참고하세요.

## 개발자를 위한 정보

- **기술 스택**: 바닐라 JavaScript(ES Modules), 프레임워크·빌드 도구
  없음. 암호화는 브라우저 내장 WebCrypto + 벤더링한 `nostr-tools`
  (`vendor/nostr-tools.js`, 버전은 `vendor/VERSION.txt` 참고).
- **전방 비밀성**: `js/pfs.js`가 Signal 방식 더블 래칫을 구현합니다.
  `node test/pfs.test.mjs`로 44개 테스트를 실행할 수 있습니다.
- **파일 구조**와 **암호화·네트워킹·저장소 사양**은 전부 `PLAN.md`에
  정의되어 있습니다. 이 사양을 벗어나는 변경은 하지 않는 것이 원칙입니다.
- **도우미 데몬**: `helper/` 폴더, Node.js 20 기반. 설치 방법은
  [`helper/README.md`](./helper/README.md)를 참고하세요.
